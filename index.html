Atajo de comandos

Comandos útiles de CMD

Información y ayuda

# HELP

Muestra una lista de todos los comandos disponibles o ayuda específica para uno.

help help cd

# CLS (Clear Screen)

Limpia todo el texto de la terminal para empezar de cero visualmente.

cls

Navegación de directorios

# CD (Change Directory)

Cambia a la carpeta especificada. Usa .. para subir un nivel.

cd Documentos/Proyectos cd .. cd C:\Users\Desktop

# DIR

Lista todos los archivos y carpetas dentro del directorio actual.

dir

Gestión de archivos y carpetas

# MKDIR / MD

Crea una nueva carpeta o directorio.

mkdir nueva_carpeta md nueva_carpeta

# TYPE / ECHO

echo escribe texto o crea archivos. type lee el contenido de un archivo.

echo contenido > hola.txt type hola.txt

# DEL / RMDIR

del borra archivos. rmdir /s borra una carpeta y todo su contenido.

del archivo.txt rmdir /s nombre_carpeta

# MOVE / REN

Mueve archivos a otra ruta o cambia el nombre de un archivo o carpeta.

ren nombre_viejo.txt nombre_nuevo.txt move archivo.txt ./nueva_ubicacion/

Extras de desarrollador

# CODE .

Abre la carpeta actual directamente en Visual Studio Code.

code .

# EXPLORER .

Abre el Explorador de archivos de Windows en la carpeta actual.

explorer .

PowerShell (consola avanzada)

Diferencia clave: PowerShell trabaja con objetos, no solo texto. Estructura Verbo-Sustantivo y aliases tipo Linux.

Ayuda e información

# GET-HELP

Documentación detallada. -Online abre el navegador.

Get-Help Get-Service Get-Help Set-ExecutionPolicy -Online

# GET-COMMAND

Busca comandos, funciones o alias instalados.

Get-Command *network*

Navegación y archivos (aliases)

# LS / DIR / GCI

ls y dir son alias de Get-ChildItem.

ls Get-ChildItem -Hidden

# NEW-ITEM

Crea archivos o carpetas.

New-Item -Path "proyecto" -ItemType Directory New-Item -Path "log.txt" -ItemType File

# CAT / GET-CONTENT

Muestra el contenido de un archivo.

cat config.json Get-Content indices.txt -TotalCount 10

Seguridad y scripts

# SET-EXECUTIONPOLICY

Permite ejecutar scripts locales (suele requerir administrador).

Set-ExecutionPolicy RemoteSigned

Red y procesos

# TEST-CONNECTION

Similar a ping, con más detalle.

Test-Connection google.com

# GET-PROCESS

Procesos activos; combinable con Stop-Process.

Get-Process | Where-Object {$_.CPU -gt 10} Stop-Process -Name "node"

# SELECT-STRING

Busca texto dentro de archivos (estilo grep).

Select-String -Path "*.log" -Pattern "Error"

Git y GitHub

Ideas clave: Git guarda cambios en una línea de tiempo de commits. Flujo habitual: carpeta de trabajo → staging (git add) → historial local (git commit) → remoto (git push).

Enlaces

  • Instalar Git
  • GitHub

1. Referencia: comandos (orden sugerido para estudiar)

Primero una lista clara; más abajo, la guía interactiva con el mismo panel gráfico para commits y ramas.

Configuración e identidad

git --version git config --global user.name "Tu Nombre" git config --global user.email "tu@email.com" git config --global init.defaultBranch main

Repositorio local

git init git status git status -s git add archivo.txt git add . git commit -m "mensaje" git log git log --oneline --graph --decorate --all

Deshacer y comparar

git diff git restore archivo.txt git restore --staged archivo.txt git reset --soft HEAD~1 git reset --hard <commit> git revert <commit>

Ramas

git branch git branch nombre git switch nombre git switch -c nombre git checkout nombre git merge nombre git branch -d nombre git branch -D nombre

Remoto (GitHub)

git clone https://github.com/usuario/repo.git git remote -v git remote add origin https://github.com/usuario/repo.git git fetch origin git pull origin main git push -u origin main git push origin --delete rama-remota

2. Guía interactiva (gráfico fijo al hacer scroll)

El panel de la derecha (o arriba en el móvil) muestra el historial Git según el paso que tengas más visible en pantalla.

A. Subir un proyecto a GitHub (resumen)

Paso A.1

Carpeta y Git

Crea la carpeta del proyecto, ábrela en la terminal y ejecuta:

git init

El gráfico aún no tiene commits; solo preparas el repositorio.

Paso A.2

Primer commit local

git add . git commit -m "Primer commit"

Aparece el primer nodo en la línea de tiempo.

Paso A.3

Más trabajo local

Sigue el ciclo status → add → commit cuantas veces necesites.

git status git add . git commit -m "Describe el cambio"
Paso A.4

Repositorio vacío en GitHub

Crea el repo en la web (sin README si quieres evitar mezclar historiales). Copia la URL HTTPS.

git remote add origin https://github.com/USUARIO/REPO.git git branch -M main git push -u origin main

El push no dibuja otra línea aquí: solo copia tus commits al servidor. El grafo local sigue siendo el mismo.

B. Commits en el tiempo

Historial

Ver el tiempo entre commits

Cada círculo es un commit; la rama avanza hacia el más reciente.

git log --oneline
Peligro

Volver atrás y “perder” un commit en la rama

git reset --hard b mueve main al commit b. El commit c queda fuera de la rama (ghost en el dibujo).

git reset --hard b

Para historial público compartido suele preferirse git revert, que crea un commit nuevo que deshace otro sin reescribir la historia.

C. Ramas: crear, fusionar y borrar

C.1

Partimos de main estable

git switch main
C.2

Crear rama sin cambiar HEAD

git branch feature

git switch -c feature hace lo mismo y además te deja en la rama nueva.

C.3

Commits solo en feature

git switch feature git add . git commit -m "Trabajo aislado"

Observa cómo main se queda atrás y feature avanza en paralelo.

C.4

Más commits en la rama

Misma idea: la punta de feature sube; main no se mueve.

C.5

Volver a main

git switch main
C.6

Fusionar feature en main

git merge feature

Aparece el commit de fusión M con dos padres. La rama feature sigue existiendo.

C.7

Borrar la rama (solo el puntero)

git branch -d feature

No borra los commits que ya están alcanzables desde main (por ejemplo tras el merge). -D fuerza el borrado si no está fusionada.

En GitHub, tras un Pull Request mergeado sueles pulsar “Delete branch” para borrar la rama remota; localmente usa git fetch --prune para limpiar referencias.

Guía rápida de clase

Checklist para no perderte. La parte visual detallada está en la pestaña Git y GitHub, sección «Guía interactiva».

  1. Instala Git y crea cuenta en GitHub.
  2. Configura nombre y email: git config --global user.name y user.email.
  3. En tu proyecto: git init, luego ciclo add / commit.
  4. Crea repo vacío en GitHub, git remote add origin ..., git push -u origin main.
  5. Para ramas: git switch -c feature, trabajar, git switch main, git merge feature, git branch -d feature.
